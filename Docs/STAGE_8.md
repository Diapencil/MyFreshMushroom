# 단계 8 — 첫 탐험과 표고 발견

## 구현 범위

- 재배 안내를 마친 뒤 오른쪽 위 `탐험하기`로 첫 탐험에 진입한다. 한 곳뿐이므로 별도 지역 선택 메뉴는 없다.
- 같은 플레이 씬에서 메인 숲과 별도의 10×10 쿼터뷰 탐험 공간을 전환한다. GameManager와 재배 상태는 유지한다.
- 왼쪽 마우스 버튼을 누르고 드래그하면 화면 이동, 휠로 확대·축소한다. 드래그를 마친 지점을 채집 클릭으로 처리하지 않는다.
- 현재 Input System의 정규화된 휠 입력에 맞춰 확대·축소 감도를 적용한다. Exploration Manager의 `Zoom Sensitivity` 기본값은 `0.2`이며 Inspector에서 조절할 수 있다.
- 통나무와 표고는 처음부터 고정 위치에 배치한다. 확률·조사 단계·통나무 클릭으로 생성하는 과정은 없다.
- 표고를 한 번 클릭하면 표고버섯 3개를 즉시 지급하고 발견 상태를 기록한다. 작은 그림도 누르기 편하도록 판정 영역을 확보했다.
- 채집 후 표고는 사라지고, 다시 탐험해도 중복 지급하지 않는다. 일반 반복 탐험·재출현은 구현하지 않는다.
- `숲으로 돌아가기`를 누르면 기존 카메라와 재배 숲을 복원한다. 탐험 중에도 재배는 진행하며, 튜토리얼 메시지를 읽는 동안만 일시정지한다.
- 보유량 UI에 발견한 표고버섯도 표시한다. 후속 확장으로 표고 종균 레시피·통나무 재배 시설을 연결했다. 상세 내용은 [표고 재배 프로토타입](SHIITAKE_PROTOTYPE.md)을 참고한다.

## 튜토리얼

재배 7단계 → 첫 탐험 안내 → 탐험 진입 → 드래그·휠·버섯 클릭 설명 → 표고 획득 → 튜토리얼 완료 순서다.

탐험 진입이나 카메라 조작만으로 완료 처리하지 않는다. 표고 보유량과 최초 획득 상태가 반영된 후 실제 획득 성공 결과로 완료한다. 첫 탐험을 도중에 나와도 나중에 다시 들어가 발견을 이어갈 수 있다.

현재 진행은 플레이 세션에만 기록한다. 파일 저장은 없어서 Play를 재시작하면 첫 발견도 초기화된다.

## 주요 파일과 설정

- `ExplorationService`: 진입 가능 여부, 최초 획득·발견·중복 방지.
- `ExplorationManager`: 화면과 카메라 전환, 고정 탐험 맵 생성, 마우스 팬·확대축소·채집.
- `GameManager`: 발견용 표고 정의 등록과 탐험 서비스 연결.
- `TutorialManager`: 첫 탐험 안내와 표고 획득 후 완료 판정.
- `InventoryPanel`, `ProgressState`: 발견 상태 변경 시 종류별 보유량 갱신.
- `Assets/Data/Mushrooms/ShiitakeMushroom.asset`: 표고 ID·이름·아이콘과 후속 확장의 테스트용 재배 설정.
- `Assets/Art/Prototype/Exploration`: 임시 통나무·표고 그림.
- `SampleScene`: 탐험 매니저와 진입·복귀 버튼, 안내 패널 참조를 연결했다. 추가 수동 연결은 없다.

시설 건설·이동·철거(단계 7)는 계속 보류한다. 느타리 성장 시간은 테스트용 9초다.

## 직접 확인

1. SampleScene을 다시 열고 Play. 튜토리얼 재배 안내 후 `계속`을 누르고 오른쪽 위 `탐험하기`를 선택한다.
2. 탐험 설명의 `계속`을 누른다. 드래그와 휠을 사용해 통나무 옆 표고를 찾아 한 번 클릭한다.
3. 표고 3개 표시와 튜토리얼 완료를 확인한다. `계속` 후 숲으로 복귀한다.
4. 재진입해 표고가 다시 지급되지 않는지 확인한다.

탐험만 빠르게 보려면 **Play 전에** GameManager의 `Enable Tutorial`을 끈다. 이 경우 시작부터 탐험할 수 있다.

검증: 코드 컴파일 성공. 실제 서비스와 튜토리얼 소스를 사용하는 짧은 검사에서 탐험 중 성장, 표고 3개 지급·발견, 중복 호출·재진입 보호, 튜토리얼 완료 전환을 확인했다. 검사는 Unity 에셋 로딩 대신 데이터 대역을 사용했다. Unity Play, 화면 배치·카메라 조작은 직접 검증하지 않았다.
